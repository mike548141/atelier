- [ ] 🎯 **Mint the evidence-window rule as guard-design doctrine — Mike's
      call.** Proposed wording: *a guard may only enforce a rule whose
      licensing context fits inside its evidence window; where the context that
      would license an exception is outside what the guard can see, the rule is
      directive, or the window must be widened before the check is built.*
      Grounds: it is the one predicate that fits every recorded divergence in
      this estate, and it is falsifiable — you can ask it of a proposed check
      before building, which is what the current record shows nobody could do.
      The four first-of-kind scanner cold passes each independently returned the
      same finding shape (sound rule, wrong scope, not gateable as built), and
      four guard builds were killed or shelved on measurement. Roughly one build
      in three did not survive contact with its own corpus. The rule would have
      predicted each of them.
      **Where it would live:** `GUARDS.md`, which today governs what happens
      *after* a guard fires and says nothing about what may be built. This adds
      the prior question. **Not adopted silently** — it is a doctrine addition
      to a self-authored doc, so it carries a rule-4 `⏳` when it lands, and the
      decision to land it at all is Mike's.
      **The honest cost:** it is a bar that some existing guards fail. Naming it
      makes their scope reductions look like defects rather than tuning, which
      is either the point or an argument against, depending on how much appetite
      there is for re-opening settled scopes.
