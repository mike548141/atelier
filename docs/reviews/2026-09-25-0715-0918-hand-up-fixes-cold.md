## Findings

### HF1 — MODERATE — the sync-bookend paragraph states a mechanism git does not have, and misses the one it does
`docs/method/CONCURRENCY.md` § *Integration hygiene*, **Sync bookends**: "onto
a stash stack shared by the primary checkout and every worktree … never a step
that shelves the peer's work where a second session may pop it." Measured
(P1): a non-conflicting `git pull --rebase --autostash` over a peer's staged,
unstaged and untracked state leaves the stash list and stash reflog empty —
the autostash is created and re-applied without touching `refs/stash`. The
shared-stack exposure exists only on a conflicting re-apply (P2), and then the
tree is *also* left with conflict markers in the peer's file. The harm on the
plain path is that the peer's **staged** files return **unstaged** — the exact
shape of the 2026-09-06 near-miss the paragraph cites (five staged files). A
doctrine sentence that names a rarer harm and omits the common one will be
"checked against git" by the next child and found wanting, which is how
`320/210` arrived in the first place. The gate itself is correct.
*Counsel:* keep the gate; replace the mechanism clause with the measured one:
autostash re-applies whatever was dirty without its index state, so a peer's
staged work comes back unstaged, and on a collision their file is left with
conflict markers and their change on the shared stash stack.

### HF2 — MODERATE — the drift check reads "current" when its fetch fails
The block, the template and PROPAGATION point 4 prescribe `fetch -q` *then*
`log --oneline <SHA>..origin/main` as two commands joined by prose. P6: with the
remote unreachable and the house one commit ahead of the pin, `fetch` exits 128
on stderr and `log` prints nothing with exit 0 — the empty output the bullet
says means "current". The same commit's **Verify the act** bullet names this
exact class ("a grep for failure markers that matches nothing is
indistinguishable from a command that produced nothing"). Board item
`030/110`'s suggested form used `&&`, which P6 shows exits 128 for the chain.
Related, same shape: an atelier checkout whose remote is not named `origin`
makes the `log` fail with exit 128 and empty stdout (P5a); the bullet does not
state the `origin` assumption.
*Counsel:* join with `&&`, add one clause — a fetch error is *no result*, not
*no drift* — and state that the parent checkout's published-mainline remote is
assumed to be `origin`.

### HF5 — minor — gate 2's stated reason is not the mechanism
"A repo with no upstream … keeps the stash hazard." P3a/P3b: with no upstream

*Counsel:* "gains nothing, and fails with a hint that invites a wrong repair."

### HF6 — minor — the bookend cannot run in the worktree gate 1 routes you to
Gate 1 sends a session that finds a peer's dirty work to a worktree. There,
