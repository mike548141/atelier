## What the work is (established from the source and HEAD)

A first-of-kind Markdown scanner for the half `linkscan` cannot see: a repo path
named in **bare prose or a single-backtick span**, with no `](…)` around it.
Fenced blocks, angle-bracket placeholders, scheme URLs and link destinations are
blanked first; what remains is matched for 2+-segment path-shaped tokens; a token
is a candidate only if it starts with one of eight known top-level directories
**or** ends in one of eight known extensions; a candidate passes if it exists
under any of three anchors (scan root, the file's own directory, the outermost
enclosing `docs/`). Exemptions: same-line `TODO`/`(none yet)` cue, glob
wildcards, `path/to…`, trailing ellipsis, `pathscan:allow:` marker,
`.pathscanignore`.

## Attack surface (the reviewer's own, committed before any live run)

**P1 — The module's own status claim.** The docstring opens *"FIRST-OF-KIND, NOT
YET WIRED… it is not invoked from `ci.yml`."* `ci.yml` appears to invoke it.
Verify; if it does, the file's most prominent self-description is false, and a
reader calibrating trust off that paragraph is calibrating off a stale fact.

**P2 — The wired scope may exclude the very shape that motivated the tool.** The
build's three citations are led by *a README listing `docs/decisions/` before it
existed*. The default target is `<root>/docs`, and the CI step passes `docs`. If
root-level `README.md` / `CLAUDE.md` / `CHANGELOG.md` are outside the scanned
tree, the scanner does not cover its own motivating case. This is the WS1 shape
(gate scope, not detection) and is the sharpest thing a gate-readiness call turns
on.

**P3 — Anchor #3 is hardcoded to the literal name `docs`, in a tool built to
travel.** `_outermost_named_ancestor(md_file, "docs")` and `main()`'s default
target both assume the records tree is called `docs/`. The floor registry has a
configurable `docs` key precisely because *not every child keeps records in
`docs/`*. A child that sets it gets the scanner at its noisiest with its dominant
anchor dead. Portability, and it bears directly on whether this can ever be a
fleet check rather than an atelier one.

**P4 — Widening "resolves" drops true findings as well as false ones.** The
docstring argues stacking anchors is safe because it *"can only ever DROP a
finding, never invent one."* That is only a safety argument if every dropped
finding is false. A reference that is wrong *at the anchor the author meant* but
happens to exist under a different one resolves silently. Attack whether the
safety framing is doing more work than it has earned.

**P5 — Candidate tokens are not constrained to the repo.** The token character
class admits `.`, so `..` segments are legal in a candidate. `(root / token)`
and `(md_file.parent / token)` would then resolve *outside* the scan root, and
`.exists()` follows symlinks. For a scanner whose entire claim is "this repo's
named paths exist", a candidate resolving against something outside the repo is a
false negative — and a scanner probing the host filesystem outside its root is
worth stating even where the impact is small (lens 4 runs at every altitude).

**P6 — The stub exemption is line-wide and cue-cheap.** Any `\btodo\b` anywhere
on a line, case-insensitively, exempts **every** candidate on that line. In a
records repo that discusses its own conventions, "TODO" occurs in ordinary prose.
Attack the false-negative surface, and whether the exemption is visible anywhere
in the output (an exemption nobody can see is the failure mode this estate's
doctrine names repeatedly).

**P7 — The heuristic's two legs are not equally defensible, and only one is
atelier-independent.** `KNOWN_TOP_DIRS` is an atelier-shaped list; in any child
with `src/`, `inventory/`, `lib/` it never fires, leaving the extension-suffix
leg — the noisier one — carrying the whole check. Attack what the precision
actually is per leg on this corpus, since a gate decision needs that split, not
an aggregate.

**P8 — Re-run every recorded proof.** The pointer records a 174-finding baseline
on `docs/` with 38 in the README-without-`.md` class. Re-run both numbers at
HEAD; a baseline recorded four days ago is a claim, not a measurement.

**P9 — The registry question ADR 0008 just raised.** `pathscan` is invoked as a
bespoke step in atelier's `ci.yml`, outside `tools/floor.py`. ADR 0008 (2026-07-25)
holds that a repo calls the floor and never keeps its own list, and that *"the
parent is not special."* The wiring predates the ADR, so this is a residual
rather than a violation — but if the answer to "wire it wider" is yes, the
registry is where it belongs, and that should be decided in the same breath.

**P10 — Error paths and the empty-scan class.** A scan that reads nothing must
never report clean. `main()` returns 2 for a missing root and missing targets;
check that the same holds for an `.pathscanignore` that nets everything, a target
directory containing no Markdown, and an unreadable file mid-walk.

## Findings

### PS1 — MAJOR (gate scope — the WS1 shape) · The wired scope excludes the case that motivated the scanner, and cannot be widened until a fourth anchor exists

The docstring's lead citation is *`foundation H2` — a README listing
`docs/decisions/` before it existed*. The default target is `<root>/docs` and the
CI step passes `docs`, so **root-level `README.md`, `CLAUDE.md` and `CHANGELOG.md`
are never scanned**. The scanner does not cover its own motivating example.

Measured, whole-repo versus wired scope:

```
pathscan --root . docs   → 174 findings
pathscan --root . .      → 239 findings   (65 of them outside docs/)
```

The 65 are not an argument for simply widening the scope, and this is the
substantive half of the finding. Their dominant shape is:

```
CHANGELOG.md:198   reviews/2026-07-22-1215-v2-plugin-deinstance-cold.md
CHANGELOG.md:247   sessions/2026-07-22-1025-security-canon-gap-map.md
```

Both targets **exist**, under `docs/`. A root-level file writing `reviews/…`
means `docs/reviews/…` — the same prefix-dropping convention anchor #3 was built
for — but anchor #3 only fires for files that are *themselves* under a `docs/`
ancestor, which a root-level file is not. So today, widening the scope would add
~65 findings that are overwhelmingly anchor artefacts rather than stale paths,
and the gate would be unusable.

**The fix is one anchor, not a scope retreat**: add `<root>/docs/<token>` (or
the configured records dir) as a fourth anchor. Widening what resolves can only
drop findings, so it cannot invent noise; it makes root-level files scannable;
and it is what lets the motivating README case actually be checked. Sequence:
add the anchor → re-baseline over the whole tree → *then* decide the gated scope.

**Gate-readiness call: NOT ready**, and the blocker is scope and anchoring, not
detection — the same verdict shape S1 (`wrapscan`) reached, for the same
structural reason.

### PS2 — minor · The module's most prominent self-description is false at HEAD

The docstring's status paragraph reads *"FIRST-OF-KIND, NOT YET WIRED, NOT YET
REVIEWED. This tool stands alone: it is not invoked from `ci.yml`, …"*.

`ci.yml` invokes it:

```yaml
- name: pathscan (named-path resolution — advisory, not yet reviewed)
  run: python3 tools/pathscan.py --warn --root . docs
```

The wiring is correct and advisory; the paragraph describing it is stale. This is
exactly lens 2 — a reader calibrating trust off the file's own status line
calibrates off a fact that stopped being true when the step landed. One sentence.

### PS3 — minor (portability) · Both halves of the heuristic are atelier-shaped, in a tool built to travel

Two hard-codings:

- `_outermost_named_ancestor(md_file, "docs")` and `main()`'s default target
  assume the records tree is literally named `docs/`. The floor registry carries
  a configurable `docs` key precisely because *not every child keeps records in
  `docs/`* — a child that sets it gets its **dominant anchor dead**.
- `KNOWN_TOP_DIRS` is an eight-entry atelier list (`docs/ tools/ skills/
  commands/ instruments/ .github/ .claude/ .claude-plugin/`). In a child with
  `src/`, `lib/`, or an inventory tree, that leg **never fires**, leaving the
  extension leg carrying the entire check.

So in a child repo the scanner is simultaneously at its least precise and its
least anchored. That does not block atelier-local use, but it decides whether
this can ever join the shared floor — and it should be settled before, not
after, anyone wires it fleet-wide.

### PS4 — minor (correctness · lens 4) · A candidate can escape the scan root and resolve against a file outside the repo

The token character class admits `.`, so `..` segments are legal candidates, and
neither `_resolves` nor `scan_text` constrains the resolved path to the root.
`Path.exists()` additionally follows symlinks.

**Reproduced**, fixture repo with a sibling directory outside it:

```
`../../../etc/hosts.py`   → flagged (does not exist)     ← traversal is attempted
`../outside/real.py`      → NOT flagged                  ← resolved OUTSIDE the repo
```

For a scanner whose entire claim is *"a doc that names a repo path must have that
path exist"*, a candidate satisfied by something outside the repo is a false
negative by construction. The impact is bounded — existence checks only, no file
is read, and the escape has to be written into a doc — but the fix is small:
resolve and require the result to be under the scan root, else flag it.

**Recurrence prevention**: this is the class ("a check that answers from outside
its own scope"), not just the instance; the same constraint belongs in whatever
anchor list PS1 adds, or the fourth anchor inherits the hole.

### PS5 — LOW · The stub cue exempts a whole line on any `todo` in ordinary prose, invisibly — latent, with zero live instances

`_is_stub_marked` matches `\btodo\b` case-insensitively **anywhere** on a line
and exempts every candidate on it. In a repo whose doctrine discusses TODO
markers, that fires on ordinary prose. Reproduced:

```
"the TODO convention aside, `docs/definitely-missing.md` is gone"   → not flagged
"a plain line naming `docs/definitely-missing-2.md`"                → flagged
```

**Measured on the live corpus: 0 candidates are currently suppressed this way**
that would otherwise fail — so this is latent, not active, which is why it is LOW
rather than minor. Worth tightening to a marker shape (`<!-- TODO`, `TODO:`)
rather than a bare word, and worth surfacing suppressed lines in `--json` so the
exemption is countable rather than invisible.

### PS6 — LOW · "Widening can only DROP a finding, never invent one" is a soundness claim doing safety's work

The docstring justifies stacking anchors on the ground that widening cannot
invent findings. True, and it is the right argument for *why adding an anchor is
safe to try*. It is not an argument that the dropped findings were false: a
reference that is wrong at the anchor its author meant, but happens to exist
under a different one, resolves silently and is gone.

That is a real precision ceiling, and PS1's fourth anchor raises it further —
four anchors means four chances for a wrong path to be right by accident. Not a
reason to skip the anchor; a reason to state the ceiling in the residuals beside
it, where today the framing reads as unqualified safety.

### PS7 — nit · A scan that reads nothing still reports clean

```
.pathscanignore containing `*`      → "✓ pathscan clean", exit 0
target directory with no Markdown   → "✓ pathscan clean", exit 0
```

Consistent with the sibling scanners, so not a defect against house convention.
Noted because this module holds the opposite rule three lines from `main()`'s
exit — *"A typo'd path scanning nothing must never read as a clean pass"* — for
missing targets, and the same reasoning covers a scan whose ignore file nets
everything.

### PS8 — LOW (residual, not a violation) · The bespoke `ci.yml` step is the pattern ADR 0008 removed

`pathscan` runs as its own step in atelier's `ci.yml` rather than through
`tools/floor.py`. ADR 0008 (2026-07-25) holds that a repo calls the floor and
never keeps its own list, and that *"the parent is not special."* The wiring
(`b738f21`) predates the ADR, so this is inherited, not a breach — but if the
gate decision is "wire it wider", the registry is where it belongs, with an
`advisory` declaration in `.atelier-floor.json` carrying the not-yet-gate-ready
status. Deciding the two together avoids adding a second bespoke step and then
migrating it.

## Answers to the build's own open questions

Read only after every finding above was durably written (rule 1's deferral, kept
as far as the queue allowed — see the exposure noted in the brief). Two of the
three answers **disagree with the question's premise**, which is the clearest
sign the deferral was worth keeping.

**1. Is the triple-anchor resolution defensible, or too atelier-specific?**
Defensible *and* incomplete *and* too atelier-specific — three separate answers
the single question collapses. The three anchors are each grounded in a real
corpus convention and anchor #3's outermost-not-nearest choice is correct
(`docs/build/templates/docs/` genuinely exists). But a fourth is missing (PS1),
and the literal `docs` name plus the atelier top-dir list are the portability
blocker (PS3).

**2. Should README-without-`.md` get an `.md`-append retry, or stay a residual?**
**Retry it.** Measured: all 24 `README` findings resolve if `.md` is appended;
they are 14% of the baseline and the single largest target. The convention being
matched is GitHub's own directory-index behaviour, so a reference to
`tools/README` is a *correct* reference, and flagging it is the scanner being
wrong rather than the doc. Cheap, and it removes the largest noise class outright.

**3. Is the extension-suffix-only leg the noisiest half — tighten before gating?**
**No — this is aimed at the wrong half, and tightening it would lose real
findings.** Split measured on the live baseline:

```
top-dir-prefix leg    98 findings
extension-only leg    76 findings
```

Inspecting the extension-only leg, its findings are not non-paths that
coincidentally end in `.md`. They are **genuine path references that no anchor
resolves**:

```
docs/ROADMAP-DONE.md:705   method/REPORTING.md          → does not exist anywhere
docs/ROADMAP.md:856        templates/CLAUDE.md          → real file is docs/build/templates/CLAUDE.md
docs/ROADMAP-DONE.md:1868  session-onramp/SKILL.md      → does not exist anywhere
```

So the leg is doing its job: what it surfaces is a mix of genuinely stale
references and human-shorthand references that drop intermediate directories a
reader infers. Tightening the leg would suppress both. **The lever is the anchor
model and the shorthand convention, not the candidate heuristic** — which is
PS1, and it is why the gate answer is "add the anchor, re-baseline, then decide"
rather than "trim the heuristic".
