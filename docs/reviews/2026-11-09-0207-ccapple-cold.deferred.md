## Seeded questions (the brief-writer's suspicions, a floor not a fence)

1. The filter requirement: can a filter that matches everything (`--text ''`, `--name '%'`, `--since
   1970-01-01`) satisfy it, so the required filter is a formality and the cap is the only limit?
2. `--limit`: is there an upper bound? Does `--limit 1000000` exist, and is the cap applied in SQL
   or after reading?
3. `immutable=1` on a live store mid-write: wrong results rather than errors? Does a query silently
   miss recent messages or read an inconsistent page, and does the output say so?
4. Locked notes: list only. Do snippet, title or body-preview columns leak the content of a locked
   note through the search path?
5. The Home column allowlist is by name. A future schema's new credential column: does a `SELECT *`
   or a `PRAGMA table_info` path exist (line ~1246) that reaches one?
6. Other people's content: does the Messages output carry numbers, emails, attachment paths or
   reactions beyond the need? Over-collection by default fields (lens 4)?
7. Photos: paths and recognised text. Do the place filter and output give locations? Is `near` a
   location oracle?
8. SQL built with `%` and `name.replace('"', '')` (line ~1246): is that injection-safe for a hostile
   table name in a crafted store? Does `quote()` on the path handle a `?` or `#` in the path?
9. Full Disk Access is granted to the terminal: does the instrument widen what every session on this
   machine can reach? Is that named as the cost?
10. The tests run on synthetic stores with an empty `HOME`. Which schema versions do they model, and
   what does a real store on a newer macOS do?
11. ADR 0006's test ("the operator has no use for this") and the sentence that a future instrument
   inherits these controls: is that doctrine by function, and where do children read it?
