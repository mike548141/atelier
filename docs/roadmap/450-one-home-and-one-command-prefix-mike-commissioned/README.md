# One home and one command prefix for the collaboration's tooling (Mike commissioned, 2026-11-18)

His commission, in his words, recorded verbatim:

> Sometimes in the past we have built tools, skills, MCP servers, guards etc in
> other repos but I believe we moved all the one that relate to how I work with
> Claude into Atelier repo. IF thats not that case now, that is what I want to
> happen - but tell me before you make changes like pulling a tool from another
> repo into atelier.
>
> But when we have created claude skills or other things that use the /
> command in claude code in vscode you have selected whatever name made sense
> to you at the time.
> I would like to put all my customisation under one / command so that they
> are easy to find as a group. For example /atelier:queue-run and
> /estate-health.
>
> I am thinking we have a standard prefix like /atelier to replace existing
> commands e.g. /atelier estate-health

Then, the same session: *"Put that on the board to do. For now just assess how
much work there is in that"*, and *"And scan the repos for any
tools/guards/skills/whatever are in other repos that are better homed in
ateliers public repo as the home for things to help me work with claude"*.

So the assessment was done and nothing moved. **Every move from another repo
into atelier is told to Mike first** (his words above), item by item.
