### Lens 1 — approach and assumptions (named by me, then attacked)

- **A1. The added-lines diff is a faithful view of what a commit introduces.**
  All three staged boundary scanners rest on it. It is false under two
  ordinary user git configs (`diff.noprefix`, `diff.mnemonicPrefix`): two of
  the three parse the `+++ b/` header literally and see nothing — RC1. It is
  also lossy on where a hit sits: `conflictscan` reports the blob offset, not
  the file line, and carries git's trailing tab into the path — RC3.
- **A2. A URL's scheme, host and path never carry a credential worth
  blocking.** The delta states the path residual honestly. It does not state
  the *userinfo* residual: a bare token before the at-sign, the documented
  shape for an access token in a clone URL, sits inside the excluded span and
  passes green — and it *blocked* before 2026-09-18 — RC2. A scheme glued to a
  token plus one trailing slash also reads as URL-shaped, so the docstring's
  "no dot and no slash" guarantee is one character wide — noted under RC2.
- **A3. Git's conflict markers are exactly seven characters plus a space at
  column 0.** True by default. False under the `conflict-marker-size`
  gitattribute (git emits longer runs; the scanner is blind to them), and
  column 0 is not where a marker starts in a UTF-8-BOM file (the opener is
  missed; the closer still blocks). Neither residual is stated — RC7. Nothing
  in this repo sets the attribute; a child that does would have to know.
- **A4. One optional trailing `s` is enough plural coverage.** The delta says
  so and states the `-s`-ending miss. The `-es` (`x`/`ch`/`sh`-ending) and
  `-ies` (`y`-ending) misses are the same class and are not stated.
  False-positive surface on a child: a listed surname that is also a common
  noun gains that noun's plural as a match; the direction is fail-safe and the
  exit is the deliberate `local-term` scope, so this is a note, not a finding.
  RC9 records the documentation gap.
- **A5. Stripping control characters *after* `splitlines()` preserves line
  structure.** True for C0/C1 (verified: ESC, BEL, U+009B all neutralised).
  But `str.splitlines()` itself splits on NEL (U+0085), U+2028 and U+2029,
  which GitHub's YAML does not treat as line breaks — so a comment can be
  "ended" mid-line and a commented-out caller or run line read as live — RC5.
- **A6. Removing `board.py`'s positional action makes the bare words
  position-independent.** Only the leading position is honoured; a trailing
  bare `rebuild` now silently becomes a check — RC6.
- **A7. The registry's blocking premise — false positives rarer than the
  class stopped.** Measured where I could: `conflictscan` finds nothing on
  this tree (whole-tree run, exit 0), and this repo's doctrine quotes markers
  inline rather than at line start. The lookbehind widening in
  `HIGH_ENTROPY_RX` adds seven spans on this tree, three of which would block,
  all inside `secretscan`'s own fixtures and already allow-marked; the floor
  is green on both planes. On a *child's* tree the same widening now blocks
  long opaque IDs behind `?list=`, `?id=` and `?v=` in cited links — the
  citation class the originating item was filed about, re-opened one query
  string over — RC4. The plural widening produced no new hook-plane finding on
  this tree with the machine-local list present (the hook floor ran green
  with `--require-terms`).

`leakscan.staged_added_lines` recognise only a literal `+++ b/` header. With
`diff.noprefix=true` git emits `+++ <path>`; with `diff.mnemonicPrefix=true`
it emits `+++ i/<path>` for `--cached`. Both are ordinary per-user settings.
Under either, the parser attributes no lines to any file, the scan covers
nothing and exits 0 — live-proven in the scratch clone with a staged conflict
marker and a staged email address, both scanners green. `secretscan`'s
`7a913e2` rewrite happens to tolerate a missing `b/` (it still mis-paths under
the mnemonic form). `conflictscan` is new code in this delta whose docstring
claims secretscan's shape; `leakscan` is the plane the design says carries
full personal-data cover, and CI cannot backstop its term layer. This is the
silent-success class the tools close three other ways (absolute path, missing
path, empty scope). *Counsel:* pass `--src-prefix=a/ --dst-prefix=b/` (or
`-c diff.noprefix=false -c diff.mnemonicPrefix=false`) in all three
subprocess argvs and pin it with a test that sets the config in a scratch
repo; better, parse the `diff --git` header instead of the `+++` line.
Recurrence prevention: the three parsers are one function in three files —
the `115/080` part-2 single-sourcing is the structural fix.

**RC2 — MODERATE.** *The URL carve-out hides a bare userinfo token, and that
shape blocked before 2026-09-18.* `_url_spans` excludes everything from the
scheme to the first `?` or `#`, and requires only a `.` or `/` somewhere after
the scheme — so a token placed between `://` and the at-sign sits inside the
excluded span. An unprefixed mixed-class token there scored as a blocking
entropy hit before the change and is now counted as a "published-url token"
and passed. The `basic-auth-url` rule needs a colon, so it does not fire. The
documented residual names the path only. Also within this finding: a scheme,
a token and one trailing slash is enough to be "URL-shaped", which makes the
docstring's no-dot-no-slash guarantee one character wide. *Counsel:* end the
excluded span at the last at-sign before the first `/` after `://` (never
exclude userinfo), or treat any at-sign in host position as disqualifying the
span; add the userinfo case to the residual statement in the module comment
and `tools/README.md`, to `test_secretscan.py` and to the selftest.

**RC3 — MODERATE.** *`conflictscan --staged` reports the blob offset, not the
file line, and carries git's trailing tab into the path.* The 320/290 defect
fixed in `secretscan` the same day is present in this new scanner: findings on
a two-hunk file were reported at lines 5/7/9 for markers at 705/707/709, and
a spaced path printed with a literal tab. Blocking still happens, so nothing
passes; the report sends the committer to the wrong place. `leakscan --staged`
has the same two defects (harvest; not in this delta's paths). *Counsel:* lift
`secretscan`'s hunk-header counter and tab strip verbatim — or single-source
the parser.

**RC4 — MODERATE.** *The `HIGH_ENTROPY_RX` lookbehind widening re-opens a
citation false-positive class on children.* Removing `=` from the lookbehind
(right for `?sig=`) also makes every long opaque ID behind `?list=`, `?id=`
or `?v=` in a cited link a blocking entropy hit where it was invisible before
— live-proven on synthetic playlist, open-by-id and cache-busted image links,
all blocking, none matched by the old regex. The originating item was filed by
a child blocked on its citations; the tightening measured this tree only (no
such links here) and the widening's child-tree surface is unmeasured.
*Counsel:* measure once across the fleet before calling it a trade; if it
bites, an unnamed query value could go to the advisory tier rather than the
block, or the URL span could keep query *keys* excluded and values live.

**RC5 — minor.** *`floorfleet`'s comment lexers can be walked past with a
Unicode line separator.* `_strip_comments` and `_live_yaml` both use
`str.splitlines()`, which splits on NEL, U+2028 and U+2029; GitHub's YAML does
not. A child `floor.yml` whose caller line sits entirely inside a `#` comment
classifies `wired` when a U+2028 or NEL precedes the `uses:` text on the same
physical line; the parent lexer reads a commented run line as live the same
way. The strip added in this delta does not reach U+2028/U+2029 (not control
characters) and runs after the split for NEL. `--status` still exposes the
missing run history. *Counsel:* split on `\n` (after dropping `\r`) instead
of `splitlines()`, in both lexers.

**RC6 — minor.** *A trailing bare `rebuild` is silently a check.*
`board.py --root X rebuild` strips no legacy word (only `argv[0]` is
examined), absorbs `rebuild` into `paths`, defaults to check, and prints
"stale — run rebuild" without rebuilding. The old positional-with-choices
signature honoured that order. *Counsel:* reject a bare `check`/`rebuild`
token anywhere in `paths` with a one-line hint (the board location is fixed,
so it can never be a real scope), or honour it anywhere.

**RC7 — minor.** *Two unstated `conflictscan` residuals.* (a) The
`conflict-marker-size` gitattribute makes git emit markers longer than seven
characters; the scanner's fixed `{7}` never matches them and the docstring's
"seven-character rule" does not say so. (b) A UTF-8 BOM on line 1 puts the
opener at column 1; the opener is missed, the separator is not gated open,
and only the closer blocks. State both beside the existing residual; a BOM
strip on line 1 is cheap if wanted.

**RC8 — minor.** *`secretscan`'s header test widened from `+++ b/` to
`+++ `.* An added line that begins `++ ` (a doc quoting a unified diff is the
realistic source) now reads as a file header; the findings that follow are
attributed to a phantom path and ignore-globs are evaluated against it.
Nothing is skipped unless the phantom path matches a glob. Pre-existing for
the `++ b/` spelling; wider now. *Counsel:* parse `diff --git a/… b/…` for
the path and treat `+++` only as confirmation, or fix the prefixes per RC1
and require `b/` again.

**RC9 — minor.** *The plural rule is undocumented where the scanner is
documented.* `tools/README.md`'s `leakscan` section carries no mention; the
rule lives in the example terms file and the changelog. The stated miss
covers `-s`-ending terms only; `-es` and `-ies` plurals are the same
one-literal-`s` limit and are unstated in both places.
