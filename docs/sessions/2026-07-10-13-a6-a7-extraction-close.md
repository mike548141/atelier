**§13 source-acquisition escalation ladder (A6).** The *active* counterpart to
§3, which only records acquisition risk passively. When a claim matters more than
its current rung supports, climb: recall → search-snippet → direct fetch →
tool-call/structured-export → independent corroboration → reproduce-it-yourself.
The load-bearing line: **the rung you stop at is set by the cost of being wrong,
not the cost of climbing.** Blocked-from-climbing is not permission to promote the
weak rung — it's a gap to *state* (else it's §2's cardinal sin by another route).
And don't over-climb: §11 — spend the budget where the model is weak, not
re-confirming fluent recall.

**§14 honest-instrument doctrine (A7).** The agent doesn't only cite evidence, it
*builds the instruments that produce it* (validator, diagnostic, plan/apply verb,
test, scan). Each instrument's own "ok"/"applied"/"12 passed" is itself a claim
the apex governs: success means **verified not attempted** ("returned 0" ≠ "I
observed it work"); **silent success is a defect equal to silent failure**
(PRINCIPLES §6); **"unknown" is a required output** (never default the uncertain
case to success); the instrument **carries provenance too** (read-back vs
assumed); and the machine enforcement is a **known-failure test** — drive the tool
through a failure and assert it reports the failure. This is §1–§4 turned on the
tools the agent makes; the phantom-success bug class is the §0-worst defect
mechanised into code where no reviewer re-reads it.
