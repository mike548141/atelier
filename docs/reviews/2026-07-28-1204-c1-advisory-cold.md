## Lens findings

**C1F1 (minor — correctness, lens 2): the advisory `why` displaces the
TA3 drift note in the human render.** `render()` builds the line note as
`reason` *else* `partial`, and C1 now populates `reason` for every
advisory result. Live probe: a softened scanner with a valid advisory and
a half-missing scope renders `🟡 … (clearing backlog) [review by …]` — the
"1 of 2 scope paths missing" note survives only in `--json`. The reader
sees a 🟡 whose visible cause is the advisory, while the mark is actually
the drift's; the drift TA3 exists to surface is invisible exactly when the
check is softened — and a softened check with shrinking cover is the
board's worst-informed case. Remedy shape: join the notes rather than
choose one.

**C1F2 (note — completeness, lens 3): the days-standing count is
board-only.** The commit message says an expired advisory renders red on
the floor and the fleet board "with how many days it has been standing";
`_days_over` lives only in `floorfleet`, and the floor line says
`— PASSED]` with no count. The board is where the ruling put the pressure,
so this may be exactly as intended — but either the floor line gains the
count or the claim should say the count is the board's. Which one is
Mike's call.

**C1F3 (note — security observation, lens 4, pre-existing class):**
config-supplied strings (`why`, disabled reasons, local `why`) print raw
to terminals from both floor and board, so a child config can embed
terminal escape sequences in text an operator reads. Not introduced by C1
— `disabled` reasons always printed raw — but C1 adds two more
config-authored strings to that surface. Cheap class fix if ever wanted:
strip C0 controls at parse. Recorded so the class is on the record rather
than re-discovered per field.
