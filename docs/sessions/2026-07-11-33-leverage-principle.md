# 2026-07-11 · PRINCIPLES §8 — leverage / "productive laziness" (Opus)

Mike named a principle mid-session and asked it be written so it makes sense to
Claude models going forward: *being lazy isn't always bad — doing something now
that avoids or saves a lot of work later is beneficial, whether by a design
decision that avoids the work, or by doing the hard work now to build a reliable,
reusable tool that saves time later and gives more consistent, robust outputs.*

## Where it landed — a new §8, not a renumber

`docs/method/PRINCIPLES.md` §8 **"Leverage — invest now to stop paying later"**,
appended after §7. Not renumbered: §5 is cross-referenced (§7 → §5), and external
docs may cite `PRINCIPLES §N`, so inserting mid-list would break refs. §8 opens by
naming itself a later addition with a meta role — where §1–7 say *how* to build
well, §8 says *how much* to build and *when*.

Two forms, each grounded in atelier's own practice (not invented for the heading —
the repo already *is* this principle):
- **Design out the work** — thin-anchor-fat-pointer (a child links doctrine
  instead of copying → no re-sync work exists); one-source is this applied to facts.
- **Build the reliable tool once** — the scan triad (built once, gates every
  commit everywhere identically); the codified removal verb that replaced recurring
  hand-surgery (already a §7 case, now generalised). Tied to EVIDENCE §14: the tool
  the agent builds is a source the apex governs — "build the tool" means tested +
  honest, not a fragile script that moves the cost to debugging.

Plus **the discipline** (not a licence to gold-plate: payback needs *real*
recurrence or a *real* avoided class, never imagined need; over-building for a
one-off is the same waste facing the other way — KISS/rule 6; and it never buys a
shortcut through §0–§2). And a situation test **"One-off or recurring?"** so the
call is operational, with the codified-verb-vs-throwaway-script precedent.
