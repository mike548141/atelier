- [ ] 🔎 **MISSING HOUSE RULE — a "this cannot work" built only from reading is
      not accepted while a cheap, disposable test exists** `[S][doctrine]` —
      hand-up from a private child repo, filed 2026-10-11 via `PROPAGATION.md`
      § *Pointing up*. Class only: no repo, host, product, person or date
      beyond the filing date appears below. Checked first: `EVIDENCE.md`
      covers provenance and tiers for what a claim rests on, `REVIEW.md` §
      *Re-run every "live-proven" claim* covers re-running a *positive*, and
      `320/230` covers a *probe* whose silent second explanation reads as a
      negative. None says that a **negative conclusion reached by reading
      alone** is not accepted when running it would have taken minutes.

  - [ ] 🔑 **The class.** A session is asked whether something can be done. It
        reads documentation, release notes and issue trackers, finds a reason
        the answer is no, and writes "not possible". The next sessions read
        the written verdict, re-check it against the same kinds of source, and
        confirm it. The verdict is built entirely out of reading, and each
        confirmation is the same reading again, so agreement carries no more
        weight than the first pass. In the instance, the verdict stood for
        about a week and five sessions confirmed it. A throwaway test (a
        disposable container with its own storage, no published ports it did
        not need) was finally run and showed the thing worked, in roughly
        twenty minutes.

  - [ ] 🔑 **Two contributing errors, both generic.**
        1. **Scored as a set.** The request named three components. The
           verdict tested whether all three could coexist, found they could
           not, and answered no to the request. One of the three worked on
           its own, and the verdict's own table said so before dropping it.
           A request for three things is not a request for a set. The negative
           should be stated per component, with the working part offered.
        2. **A document looks like progress.** Research produces a page; a
           throwaway test produces one word, worked or did not. The page
           feels like more work done and so wins over the word that is worth
           more. The method already says this for configuration ("validated
           means it started, not that it parsed"); it is not extended to
           conclusions, which is where it is needed most.

  - [ ] 🎯 **Proposed rule (for the house to word and place).** Before a
        session records that something cannot work, it asks whether a cheap,
        safe, disposable test exists. If it does, the test is run and the
        result is what gets written; "I read that it will not work" is not
        accepted as the answer, from another session or from oneself. If no
        such test exists, the verdict says so and is labelled as reading-only
        (`ai-inference` / secondary tier, `EVIDENCE.md` §2), not stated as
        fact. A negative on a multi-part request is stated per part.

  - [ ] ⚠️ **Where caution still belongs.** Anything that touches live data,
        costs money, or cannot be undone stays under the existing stops. The
        test of whether to run it is disposability, and most tests are.
