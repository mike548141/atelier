- [ ] 🎯 **No doctrine covers a session with no tree — decide what a repo-less
      session reads, keeps, and hands on.**
  - [ ] 🔑 **Three gaps, kept separate:**
    - **Onramp.** Nothing tells a repo-less session which house rules apply
      to it; it gets only what the person-level instructions happen to say.
    - **Record and close.** § *Declare session close* and the session-log
      rule have nowhere to land, so a small job either leaves no trace or a
      trace in memory only (one such memory is already cited from the
      person-level instructions as the home of a reusable method).
    - **Hand-on.** A shaping session's output is an idea for *some* repo.
      Today it reaches that repo only if Mike carries it across by hand —
      `310/140` (a PR as the carrier) and `280/050` (talk first to a live
      session in that repo) are both candidate routes out.
  - [ ] 🤔 **Candidates, none chosen:** a thin home-directory onramp that
        points at the house doctrine and says which parts bind; a standing
        scratch repo that repo-less work defaults into; or a rule that a
        session which finds itself shaping a repo's work moves to that repo
        before recording anything. The second is the cheapest to try and
        the most likely to become a dumping ground.
  - [ ] 🚩 **The privacy line matters more here, not less.** A repo-less
        session is where person-level context is closest to hand; whatever
        route carries its output into a repo — especially a public one —
        must carry the no-personal-data boundary with it.
  - [ ] 📎 **Related:** `240` (context follows the person — the device side of
        the same question), `360/020` (repo-less sessions are invisible to
        every per-repo coordination rule).
