### Findings

- **DSR1 — minor (latent silent-miss + mis-stated rationale).** `datescan.py:208`
  / header line 42. Blockquote lines are skipped whole, justified as "a quoted
  external source's own words are not this repo's dating claim" — but `>` is also
  the house's own-content callout style (`AUTONOMY.md:10`; the `> 🎯 S1…S5`
  candidates in the S3 intent doc are the repo's *own* normative text). A relative
  dating claim inside such a callout is silently exempted. Latent (no current
  corpus slip hides there), but the exemption is broader than its stated grounds.
  *Direction:* narrow to attribution blockquotes, or restate the limit honestly.
- **DSR2 — minor (false-positive noise; a gate-blocker).** `datescan.py:153`
  slash-date regex `\b\d{1,2}/\d{1,2}/\d{2,4}\b` matches any numeric triple. It
  fired twice on `23/26/27` (`child-ci-floor.md:132,310`) — **session numbers,
  not a date**. 2 of 3 shape-check hits in the whole baseline are this FP.
  *Direction:* constrain fields to plausible dates (≤31/≤12) or require a
  date-context cue.
- **DSR3 — minor (signal-vs-noise; the single biggest gate-blocker).**
  `datescan.py:133` denylists `today`, but the corpus uses `today` overwhelmingly
  in the "currently / at present" sense — a weak-anchor hedge, not a date claim
  (`COMMUNICATION.md:24`, `PRINCIPLES.md:75`, `PROPAGATION.md:82`, `SIGNING.md:232`,
  `TOOLBOX.md:19`, `ECONOMICS.md:363`…). This is the exact weak-anchor class the
  header deliberately excludes for `recently`/`currently`/`soon` — but `today`
  straddles both meanings. **51 of 57 relative-word hits are `today`**, most
  currently-sense. *Direction:* accept `today` as inherently high-noise (keep
  advisory) or narrow it to date-adjacent contexts before gating.
- **DSR4 — minor (mention false-positive).** `datescan.py:236` `_is_quoted_mention`
  only exempts a word *immediately* flanked by quote chars, so a banned word inside
  a multi-word quoted example is caught: `EVIDENCE.md:101` false-positives on
  `this year` inside the doc's own banned-phrase list `"new this year"` — the
  scanner reds its sibling doctrine for correctly quoting the rule. *Direction:*
  detect the enclosing quote span, not just the two adjacent characters.
- **DSR5 — Low (under-coverage silent miss).** Non-ISO shapes pass silently:
  `23-07-2026` (dash DD-MM-YYYY) and `2026/07/23` (slash, ISO field order) both
  scan clean. Header admits non-exhaustiveness but doesn't name the dash form.
  *Direction:* add dash-DMY or name the gap in the header.
- **DSR6 — Low (noise / under-exemption).** Only *fenced* code is exempt; 4-space
  indented code blocks are not (a `tomorrow` inside one flagged). *Direction:*
  handle indented code or document that only fenced blocks are exempt.
- **DSR7 — Low (invocation wart).** The test file does bare `import datescan`, so
  `python3 -m unittest tools.test_datescan` **fails with ModuleNotFoundError**;
  only `discover -s tools` (what CI uses) or `cd tools && …` work. *Direction:*
  note the working invocation or make the import package-relative. (Matches the
  atelier-tool-invocations memory, which already prescribes `discover -s tools`.)
- **DSR8 — nit.** `datescan:allow` is a bare substring test, so any prose merely
  mentioning the marker exempts the whole line, and an empty reason is accepted.
  Sibling-scanner parity, low stakes.

### Honest positives (reviewer, unprompted)

The header is genuinely honest where it matters: the "dated maintenance edit
carries its date" clause is explicitly stated as **NOT mechanically checked**
("stays caught at review, never measured"), and the punctuation-mention
heuristic's two-way failure is spelled out. Exit-code discipline is fail-safe
(missing/typo'd path → exit 2, `errors="replace"` on read, `OSError` → 2,
invalid-ISO guarded). No bare excepts, no fail-open early returns in the scan
path.

### Gate-readiness call: NOT ready to flip advisory → blocking

The 60-finding baseline is **more noise than signal**. Reviewer's sampled
classification (~17 findings closely read + all 3 shape hits): **≈ 4 real /
~13 noise (~75% false-positive)** — the real ones being `ROADMAP.md:531`
(`15/7/26`, a genuine non-ISO date), `last night's route`, `built yesterday`.
Flipping now would red 57 files, most for currently-sense `today` and numeric
triples — training authors to sprinkle `datescan:allow`, the "noisy scanner
trains itself away" failure the house has already rejected once.

**Precondition for the flip:** fix DSR2 (numeric-triple FP), DSR3 (`today`
conflation), DSR4 (multi-word quoted mention); re-baseline to near-zero genuine
breaches (fix the real ones with an ISO date or an `allow`); *then* drop `--warn`
and add to `floor.yml`. Until then, **keep advisory — which is exactly how it
ships, so the current wiring is correct**.

### Adversarial caveat (reviewer, mandatory)

The scanner's *stated purpose* — "catch the shape of the mistake before it
lands" — is only weakly served by its loudest check. The S3 grounding findings
(`communication C3`, `concurrency-put-away 3`, `conventions-utc-applied F2`)
were about **undated** and **non-UTC** records — not one was a relative-time-word
misuse. The relative-word denylist produces 57 of 60 findings but has thin
corpus evidence of the specific breach it hunts, and its highest-frequency term
(`today`) is the noisiest. Well-built; aimed slightly off the mistake that
actually cost the five-file sweep.
