# 2026-07-10 · linkscan — the internal-link integrity check (Opus)

Session 23 named two unblocked next builds off going-public: wire the public
scanners into child CI, and a markdown internal-link check (deferred there as
"net-new tooling wanting its own review, not stacked onto the CI change"). Took
the second — the cleaner self-contained build, and the one that guards the thing
atelier's whole doctrine leans on. The architecture is "thin anchor, fat pointer"
(PROPAGATION): a child inlines a floor and points up; a doc states a bearing and
points to case-law. That graph is only as sound as its links. A relative link
that 404s — a renamed file, a moved doc, a typo'd `#anchor` — is a silent hole
the *reader* hits, not the author. So: build the machine that catches it first.

## What landed

`tools/linkscan.py` — the sixth house tool, same pattern as the scan triad
(zero-dep stdlib, `--selftest`, `linkscan:allow` + `.linkscanignore` hatches,
fail-safe `0`/`1`/`2`). Deliberately narrow, because a broad flaky link checker
is worse than a sharp honest one:

- **Internal `[text](path)` / `![alt](path)` links only.** External schemes
  (`http`/`mailto`/…) and `//host` are skipped — verifying them means the network,
  which is a different, flakier tool's job.
- **`missing-file`** — the path must resolve (relative to the linking file, or the
  repo root for a leading `/`) to a real file *or* directory.
- **`missing-anchor`** — a `#fragment` into a Markdown target (or same-file) must
  match a heading by GitHub's slug algorithm. `#L42` line refs and anchors into
  non-Markdown targets are skipped (nothing to validate against).
- Fenced (` ``` `) and inline (`` `…` ``) code is stripped so example links don't
  false-positive; `[[name]]` wiki links are out of scope by design.

`tools/test_linkscan.py` — 26 stdlib tests (slugify edge cases, duplicate-heading
suffixes, fence/inline-code stripping, allow-marker, target-split, angle-bracket +
titled destinations, and an end-to-end tree covering relative up/down,
root-relative, dir targets, anchor-into-non-markdown, ignore glob, missing
file/anchor). Suite **145→171**.

## Held, on purpose

linkscan is **not wired into `ci.yml` or `pre-commit.sample`.** It's net-new
tooling in the same class as the scan triad — a check destined to be a gate, where
a clean exit is read by automation as "safe". The sharpest failure mode is the
**false negative**: a real broken pointer it doesn't see, reported green — worse
than no check, because it manufactures confidence in exactly the graph the
doctrine leans on. So the gate-wiring waits for a review: brief
`docs/reviews/2026-07-10-linkscan.md` (false-negative surface the top lens;
slugger-flags-a-valid-anchor and code-stripping-side-effects the assumptions to
attack). Third application of don't-stack-a-gate-on-unreviewed-tooling, after the
method layer and the create-repo mechanism. The honest residual is already in
`tools/README.md`: reference-style links, HTML links, setext headings, a `](…)`
split across two lines, and slugger divergence from full CommonMark are the known
blind spots.
