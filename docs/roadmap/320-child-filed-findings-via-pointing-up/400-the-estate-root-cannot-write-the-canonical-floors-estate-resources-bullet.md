- [ ] 🔎 **Hand-up: the canonical floor's `estate resources` bullet is
      unwritable by the estate root itself — it instructs a repo to reference
      a repo that it IS — and the 2026-09-19 verbatim rule has just removed
      the local adaptation that used to cover the gap.** Filed from a private
      child 2026-09-20 via § *Pointing up*, by direct write into the parent's
      tree, PR opened before stopping. The child is not named and the branch
      carries no repo token, per § *The route* rule 2 and the naming
      precedence ruled 2026-09-19.

      **What the house says today.** `PROPAGATION.md`'s canonical `floor`
      region carries nine bullets, the eighth being:

      > **Estate resources — point up, don't re-derive:** providers & account
      > plans, financial constraints & plan entitlements, licences,
      > credentials, shared estate tooling, and the estate inventory live in
      > the operator's **private estate-root repo** (atelier's private
      > counterpart). Reference it for these; never re-derive them locally or
      > copy its contents down.

      And, ruled 2026-09-19 as `115/030`:

      > **The safety floor never narrows.** A child's copy of the `floor`
      > region is the canonical text word for word — no compression, no
      > declared narrowing — and `narrow=` on a `region=floor` stamp reds
      > instead of excusing anything.

      🔑 **The two are individually fine and jointly unsatisfiable for exactly
      one repo in the estate.** The bullet is addressed to a repo that is *not*
      the estate root: it says reference **it**, never re-derive **them**,
      never copy **its** contents down. Read in the estate root, every pronoun
      turns back on the reader. It becomes an instruction to reference itself
      for facts it originates, not to re-derive what it is the sole source of,
      and not to copy down contents it holds rather than receives. That is not
      a rule the root can follow or break — it is a rule with no referent
      there.

      **Why it is a finding NOW and was not before.** Until 2026-09-19 a child
      could compress or adapt its floor copy, so an estate root could render
      the bullet in whatever form was true for it, or declare a narrowing.
      Verbatim removes both. The root's only remaining options are to copy a
      bullet that says something untrue of it, or to omit a floor bullet —
      which `narrow=` on a `region=floor` stamp now reds. **Neither is
      compliant, so the rule as written cannot be satisfied there.** This is
      the § *Pointing up* case in its intended form: a child that finds a line
      of the floor wrong reports it up rather than dropping it locally.

      🚩 **A second, larger consequence rides on the same ruling, and is
      surfaced here rather than filed separately because it is the same
      question's other half.** A long-lived child whose floor block has
      accumulated pin-bump history, measured incidents and earned lessons
      *inside* the block now has no conforming path that does not delete them.
      Verbatim adoption is, on such a repo, a **bulk deletion from a record
      store** — which `AUTONOMY.md` and `RECORD.md` make show-first, with git
      remembering the text explicitly the wrong test. So the verbatim rule and
      the show-first rule point opposite ways on the same edit, and a child
      cannot resolve that on its own authority. ⚠️ **Marked as reasoned, not
      measured, for the general case:** one child has measured its own gap
      (a floor block several times the canonical region's length, with no
      stamp markers), but no estate-wide count of affected children was taken,
      and this filing deliberately carries the class rather than that repo's
      figures.

      🤔 **Three shapes a remedy might take, offered as options and not as a
      recommendation — remediation is the parent's, and the reporting session
      stops at the report.**

    - [ ] **(a) An estate-root exception to the bullet.** Name the root as the
          one repo that carries a different eighth bullet — or none — and say
          so in the region itself, so the exception is canonical rather than a
          child's local reading.
    - [ ] **(b) Rewrite the bullet so it is true everywhere.** Phrase it about
          *where estate resources live* rather than as an instruction to
          reference another repo, so the root reads it as a statement about
          itself and a child reads it as a pointer.
    - [ ] **(c) Rule that the floor region is per-role, not universal.** The
          heaviest, and it reaches further than this bullet.

      📌 **Not asserted:** that the verbatim rule is wrong. Its reasoning — the
      floor must bind where nothing else of the child's is read — holds, and
      this finding does not argue against it. What is reported is that its
      interaction with one bullet, and with the record-store protection, has an
      unreachable state in it for at least one class of repo.
