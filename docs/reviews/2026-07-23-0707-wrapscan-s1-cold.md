### Findings

- **WS1 — MAJOR (gate-scope; baseline unusable as a gate).** The recurring
  defect the tool targets (ordinary prose at 86–122 cols) lives in the
  **doctrine surface** — and there the tool works and the corpus is nearly clean
  (`method/` ~3 genuine findings; `build/REPO-STANDARD.md:52` @126 real;
  `decisions/` bodies clean). But scanning all of `docs/**` buries that under 239
  deliberate single-line record entries (SESSIONS index rows up to 3251 cols),
  ~6:1. *Direction (reviewer's, option a preferred):* before flipping, scope the
  gate to the doctrine dirs (`method/`, `build/`, `decisions/` bodies) and
  `.wrapscanignore` the record/log/review stores — lower-risk than teaching a
  record-format exemption (option b), and matches the intent record's own stated
  home ("all `method/` docs, fleet-wide"). **This is the principal's call** (it
  shapes how the floor behaves) — see the 🎯 below.
- **WS2 — minor (fail-open).** `_is_table_row` exempts *any* line containing a
  pipe, so a long prose line with one inline `|` (shell pipeline, `A|B`, a regex)
  silently passes at any length. Honestly documented, but a silent-miss vector
  for a gate. *Direction:* require a structural signal (≥2 pipes, or leading/
  trailing `|`) before exempting; or accept + re-state in the gate-time residual.
- **WS3 — minor (unclosed fence swallows the tail).** An unterminated ``` opens a
  fence that never closes, so all subsequent content is skipped (proven by
  `test_malformed_unclosed_fence` returning `[]`, by design). Fails toward
  under-flagging — fine advisory; as a gate, one stray fence hides all later
  over-wraps. *Direction:* accept + document as a gate-time residual, or reprocess
  the tail when a fence is unclosed at EOF.
- **WS4 — minor (cross-scanner allow-marker collision).** `SIGNING.md:120` flags
  at 149 cols *solely* because a mandatory `<!-- leakscan:allow: … -->` marker
  pads an otherwise-short line, and the marker contract requires the reason stay
  on the same line (can't wrap). wrapscan only recognises its own `wrapscan:allow`.
  *Direction:* exempt a line whose overflow is caused by a trailing
  `<!-- <name>scan:allow: … -->` marker for any sibling scanner.
- **WS5 — Low (dotted unittest invocation fails).** `python3 -m unittest
  tools.test_wrapscan` → ModuleNotFoundError; only `discover -s tools` / `cd
  tools && …` work. Sibling-consistent wart (matches datescan DSR7). Note only.
- **WS6 — Low (`decisions/README.md` index entries, 9, flagged).** Same
  record-format class as SESSIONS; resolved by whatever fixes WS1.

### 🎯 Reviewer decision on the build's SESSIONS/verdict-files question

**Exempt via `.wrapscanignore`; do NOT reformat and do NOT add per-line prose
exemptions.** The record/index/checklist rows are a *deliberate* one-line-per-entry
format whose value is grep-ability and one-record-per-line diffs; rewrapping ~250
of them fights the format and would recur every session, and 250+ `wrapscan:allow`
markers is itself noise. **Caveat:** `docs/reviews/` and `docs/sessions/` are
*mixed* (genuine prose over-wraps alongside single-line entries), so a wholesale
ignore there suppresses real signal — cleaner is WS1 option (a): scope the gate
to the doctrine surface, leaving the record stores out by *scope*, not ignore-glob.

### Gate-readiness call: NOT ready to flip advisory → blocking

Concrete preconditions: (1) resolve WS1 — scope the gate to the doctrine surface
(or add a record-format exemption + `.wrapscanignore` the log/review/index
stores); (2) fix the ~4 genuine doctrine over-wraps (REPO-STANDARD:52,
SIGNING:83, CONCURRENCY:232) so the gated scope is clean; (3) decide WS2/WS3/WS4
(tighten or accept-and-document); (4) then a clean `--warn` run over the gated
scope is the PASS-and-clean the flip requires. Until then, **keep advisory —
exactly how it ships, so the current wiring is correct.**

### Adversarial bottom line (reviewer)

The tool is aimed at the right mistake and detects it correctly — but its *net is
mis-scoped*. The recurring defect lives in the doctrine docs, which it handles
well and nearly clean; the failure is that the default `docs/**` scope can't tell
the recurring-prose-defect class from the deliberate single-line-record class,
burying the signal. **Fix the scope, not the detector.**
