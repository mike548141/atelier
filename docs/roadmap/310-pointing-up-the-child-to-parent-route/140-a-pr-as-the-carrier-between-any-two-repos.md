- [ ] 🎯 **A PR as the carrier for an idea or finding between *any* two
      repos, not just child to atelier — Mike commissioned, 2026-09-29.**
      His words: *"PR's could be the best way for a session working in one
      repo to send an idea or whatever to another repo"*.
  - [ ] 🔑 **Half of this is already doctrine, for one direction.**
        `PROPAGATION.md` § *Pointing up* shape 1 plus § *Report without
        harming the parent* already make a PR the carrier for a child handing
        a finding up to atelier: a `report-<subject>-<HHMM>` branch, the kind
        of change said in the first line, *open the PR before you stop*, touch
        your own item only, and the parent's half — an atelier session that
        finds an orphaned report lands it. The ask generalises that to
        **sideways and downward** routes (a repo to `shed`, `shed` to a
        consumer, one estate repo to another), which today have no route at
        all (`310/120`).
  - [ ] ⚖️ **Where it meets an existing ruling.** *Work lands in the repo it
        changes* (2026-08-09) and § *What the channel is not* (*queue, never
        deliver*). A PR that **files** an idea — a board item or a request
        file in the target — is queuing and fits cleanly. A PR that carries
        the **fix itself** is delivery from another session, with the
        target's session reduced to pressing merge. Which of the two Mike
        means, or whether both are wanted, is his to rule.
  - [ ] 🚩 **Publication runs through the PR.** Branch names, PR titles and
        bodies are public on a public target; rule 2 (carry the class, never a
        private repo's specifics) already binds that for atelier. A private
        target (`shed`) could safely receive specifics — `310/120` names the
        relaxation — so the rule wants to key on the *target's* visibility.
  - [ ] 🤔 **Open:** how the target learns a PR arrived (the orphaned-report
        failure was exactly a PR nobody looked for — `310/020`'s enumerator,
        or a talk-first message per `280/050`); and whether a session with no
        write access to the target falls back to an issue.
  - [ ] 📎 Filed under `310` rather than `390` because it is the *route*
        question; `390/010` holds the *relationship* model the route would
        run along.
