## Scope

Widest the work admits: intent, decisions, assumptions, design, docs, code,
tests and live behaviour. The lenses organise it; they do not bound it.
Non-goals are the only narrowing and are themselves reviewable.

Each net, attacked at its boundary: `conflictscan` against every marker shape
git and its merge tools emit (`<<<<<<<`, `=======`, `>>>>>>>`, `|||||||`, the
seven-character rule, a marker inside a fenced code block that *documents*
markers — this repo's own doctrine does exactly that), `secretscan`'s URL
exclusion against a secret *inside* a URL (query string, userinfo, fragment) and
its entropy net against the shapes it stopped matching, `leakscan`'s plural
suffix against a term whose plural is irregular or whose singular ends in `s`,
`floorfleet`'s control strip against a `floor.yml` carrying a control character
in a place that matters. Whether removing `plainscan` from the registry left a
dangling reference anywhere the registry is read (`floorfleet`, `selftest`,
`CONTRIBUTING`, the templates). **Non-goal:** the rulings that removed
`plainscan` and added `conflictscan`.

## The four lenses

1. **Approach & assumptions.** Name the load-bearing assumptions yourself. A
   blocking net's premise is that its false positives are rarer than the class
   it stops — for each widened net, estimate the false-positive surface on
   *this* tree and on a child's (a child's docs may legitimately contain
   markers, plurals, URLs with tokens).
2. **Correctness & quality.** Read the whole of each changed tool, not only the
   diff. Run each selftest and test file. Construct the boundary cases in
   *Scope* and record what each tool prints and exits. Check `--staged` line
   numbers against a staged hunk whose line numbers differ from the worktree's.
3. **Completeness / harvest.** The registry's other readers: does `floorfleet`
   render the new scanner and the removed one correctly across the fleet's
   actual floor files? Does `tools/README.md` document every entry the registry
   has at HEAD and none it lacks? Does `CHANGELOG.md` carry the removal and the
   addition?
4. **Security & privacy** — mandatory. These tools *read secrets to find them*.
   Check `secretscan --staged` cannot print a matched secret's value to a
   terminal or a CI log (only its location and shape), check the URL exclusion
   does not create a path by which a real token in a URL passes green, and check
   `conflictscan`'s file reading does not follow symlinks out of the tree. The
   house scanner is discharged by grounds (landed delta; pending = other passes'
   drafts) — say so, and deliver the OWASP-class read by hand.
