# When to ask — keeping work flowing (Mike commissioned, 2026-10-01)

His words, sent to several sessions mid-run: *"Try not to stop and ask me
questions until you have done all the work. I won't be here to answer for
several hours and I want you to get as much of this work done as you can"*.
And the reason, filing this item: *"asking questions is often stopping work and
I don't always know the work is waiting for me. It cause slow work output,
expired cache, wasted tokens etc"* — with the frame *"Its about when to ask
rather than if you should ask I think"*.

The house already says **whether** to ask (`AUTONOMY.md` — the one rule and its
floor) and **how** the ask reaches him (`COMMUNICATION.md` § *Asking for a
ruling*). Nothing says **when**: at what point in a run a question is put, and
what happens to the rest of the work while it waits. Today an ask is a stop —
the turn ends, and every piece of work behind it waits with it, whether it
depended on the answer or not.

**Measured at filing:** the message above reached three sessions in three other
repos. Two had put six structured asks each before it arrived; none of the
three asked again afterwards.
