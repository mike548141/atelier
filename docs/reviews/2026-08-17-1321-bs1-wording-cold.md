## Findings

- **BW1 (MAJOR)** — the condition clause **"at the hook only when worktree
  and index agree" misnames the condition, on all five spellings**. Its
  literal parse is inverted: worktree-and-index agreement is the state in
  which the hook *misses* (probed — cases a and b, hook exit 0 with worktree
  items and index in agreement), and under the charitable staged-index
  reading case (b) still falsifies it, because that disagreement lives in
  the staged item file, not the index. The true condition is "only when the
  staged plane matches the worktree", covering item files as well as the
  index — the same compression BS1 was ruled to fix, one layer down. A
  reader can recover the truth only from the listed consequences, never
  from the condition the surfaces actually state.
- **BW2 (MODERATE)** — **the spellings qualify different subjects.**
  `CONCURRENCY.md` attaches the qualification to "a forgotten rebuild",
  which the hook demonstrably *does* catch (probe c, exit 1); the other
  surfaces attach it to "a commit whose index is stale", which is the true
  subject. What escapes the hook is a rebuild that *ran* — unstaged, or
  absorbing foreign state — not one that was forgotten. The doctrine doc a
  claiming session reads is the one spelling that gets the subject wrong.
- **BW3 (MODERATE)** — **a surface asserting the guarantee was missed:**
  `docs/roadmap/README.md` line 8 ("the `board` floor check blocks a commit
  whose index is stale"), the board's own preamble, unqualified, and
  pre-existing at `431f1f7^`. The commission was "state the residual on
  every surface that asserted the guarantee".
- **BW4 (MODERATE)** — **the new stop rule contradicts the unedited CF3
  decision procedure thirty lines below it.** "Claiming at a dirty primary
  checkout" still defines queue-touching as "(the item's file, and on a
  split board the generated index with it)" and sanctions staging the claim
  alone; with a dirty *sibling* item state line — your item clean, the index
  clean because no rebuild ran — that test says claim away, whereupon your
  claim's own rebuild absorbs the sibling's line (probe b's commit). The
  rule that forbids this sits italicised inside a parenthetical about the
  floor check; the procedure a reader actually executes was not widened.
- **BW5 (minor)** — `tools/board.py`'s docstring now carries **two
  unlinked accounts of the same residual**: the new BS1 clause (§ *Why the
  index is committed and checked*) and the older § *STATED RESIDUAL*, whose
  account — "caught only because the hook runs after `git add` of both or
  neither in practice" — misdescribes the mechanism (a never-run rebuild is
  caught by the worktree comparison regardless of add order; what escapes
  is a rebuild that ran but was not staged). Two spellings of one rule in
  one file, the class the delta was commissioned to end.
- **BW6 (minor)** — **"until the staged-plane check lands" is open-ended
  with no unwind.** Five spellings plus BW3's preamble will need re-editing
  when `010/020` lands; no surface points back at the wording it must
  retire, and nothing machine-checks the unwind. (Whether the funded item's
  body carries that list is rule-2 barred at phase 1 — checked at
  reconcile.)
- **BW7 (note)** — **child altitude:** "on CI unconditionally" presupposes
  a repo whose CI runs the floor; a child running the floor only at the
  hook inherits a conditional hook and no stated backstop, from doctrine
  surfaces children read. Relatedly `floor.py`'s board `why` string — "the
  generated roadmap index never drifts from its item files" — still prints
  the unqualified aspiration on `--list` and the fleet board.
- **BW8 (note)** — the wording covers only the false-pass direction. The
  hook also **reds a consistent commit** whose worktree moved after staging
  (probe d: hook 1, CI 0 on the same commit) — friction rather than a
  safety gap, but an unexplained red at the moment of committing invites
  exactly the hand-fixing the board doctrine forbids.
- **BW9 (note)** — "on CI unconditionally" carries an operational caveat no
  surface states: this repo's floor CI cancels in-progress runs on a
  superseding push, so a given stale commit's own run may never complete.
  Staleness that persists in the tree is caught by the next completed run —
  per-commit unconditional is, operationally, per-tree eventual.
