- 2026-08-10 · 0017 UTC · E8 fixed — pathscan stopped inventing a truncated path, and the report's diagnosis was wrong (Opus, wt: worktree-e8-pathscan-root-anchored) — Mike asked for the `faves`-reported bug to be investigated and fixed if the report held up. It held up, and the diagnosis in it did not. The report named dot-directories, and its own repro supported that reading honestly, because `/.well-known/security.txt` was the only shape it had to generalise from. **The trigger is a hyphen anywhere before the token's last `/`** — `/docs/some-dir/x.md` truncates to `dir/x.md`, `/a/b-c/d.md` to `c/d.md`, no dot involved. `_PATH_TOKEN`'s lookbehind excluded `\w`, `.`, `/`, `*` and `?` but not `-`, while the token class accepted `-`; a run of token characters can only be blocked at its start by a preceding `/`, since every other lookbehind character is itself in the token class and would have been eaten as part of the same run, so the hyphen was the single place a match could resync mid-token. The header had claimed since it was written that leading-`/` mentions are skipped — true only of paths carrying no hyphen, which is why the class survived a cold review behind a bullet that read as correct. **The fix is one character and an invariant**: the lookbehind must exclude every character the token class accepts, plus `/`. That is the same hole, and the same fix, as the `*`/`?` exclusion sitting two lines above it in the same comment — the second instance of that shape, so the invariant is now written down rather than re-derived a third time. **Verified on this repo's own corpus in both directions before it was believed**: the gated doctrine surface was and stayed clean; tree-wide 8 findings dropped, 208 → 200, and every one was the defect — six spellings of `repo/SKILL.md` truncated from `~/.claude/skills/create-repo/SKILL.md`, one `plugin/plugin.json` from a just-blanked `<plugin-path>` placeholder (the "tail of a just-blanked placeholder" case the header names as skipped and which demonstrably was not), and `known/security.txt` from the E8 board entry itself, the bug report being mangled by the bug it reported. No legitimate finding was lost, and a diff of the old and new regex across sixteen shapes changed exactly the three defect shapes and nothing else. Module tests 76 → 86, suite 1284 → 1294, floor green on the ci plane. **What was deliberately not done, and why it is not a hedge**: root-anchored paths are still skipped whole, so a genuinely broken one still goes unflagged. That is the docstring's named false negative, unchanged — the defect was the truncation, never the skip — and it now carries a test stating it as an accepted cost rather than leaving it to be rediscovered as a bug a third time.
