# Pointing up — the child-to-parent route (Mike commissioned 2026-08-18)

**Where this came from.** A private child's session reported, of its own
accord, that it had homed a rule in that repo's `CLAUDE.md` with "the upstream
debt to atelier marked 🎯 as one rule with four symptoms". Mike's reading:
*"That does not seem like a good precedent. Lets build whatever fills that need
properly in the doctrine and once thats ready (incl reviews etc) queue it in
cbom repo so that a cbom session can revert the changes cbom has made to
claude.md."*

**The need was real and the route did not exist.** `PROPAGATION.md` said
children point up and the parent never points down for truth; it never said
*where* a child files a rule the house owns. `GUARDS.md` § *A rule with no home
is not a rule* told the session to name a loaded surface or queue the homing —
and the only loaded surface a child session can reach is its own onramp. Both
rules were followed. The outcome was still wrong, which makes this a missing
rule rather than a session's misjudgement.

**And the debt was not real.** Verified before the doctrine was written: both
rules the child authored are already in atelier's `CONCURRENCY.md` — one
verbatim at § *Claiming work*, the other's substance at § *The trigger*. The
child had not found a gap in the house. It had reasoned against **its own floor
block's compression** of the house rule (*"read the staged hunk headers"*),
which reads as covering only what you staged, where the parent's actual rule
runs `git diff --cached` over the whole index and covers exactly the case the
child thought was uncovered.

That is the finding worth keeping, and it is one rung deeper than duplication:
**a stamped copy read as the source does not merely misinform — it manufactures
phantom debt.** The child was diligent throughout. It checked the wrong
artefact, and nothing told it that was a different act from checking.

**Two causes, both now fixed at the point of use.** The block's phrase was
lossy in the one place precision mattered, *and* its pointer named
`CONCURRENCY.md` § *The channel* where the rule lives in § *The trigger* — so a
session that did follow the pointer landed in the wrong section and found
nothing. Ten children and the scaffold template carry both defects today.

**What is deliberately not closed.** Nothing enumerates what the estate owes
the house. `floorfleet.py` and `pins.py` answer *is this child current*; the
mirror question has no instrument, so § *Pointing up* is rung 1 on its own
ladder until `020` lands. Said in the doctrine itself rather than implied away.

**Mike's ruling, 2026-08-18** (asked with the impacts of each option stated
first, after a plain-language walk-through): where a child checks the parent
properly and the rule genuinely *is* new, the child **may keep one
repo-shaped line**, marked pending-upstream and naming the parent item it waits
on — in preference to holding nothing. The reason he was given and ruled on:
forbidding the local write without removing the exposure that causes it would
leave the child knowingly unprotected between learning and landing, and that
exposure is what produced this instance.
